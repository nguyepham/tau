# Built-in Agent Model Override: LLM Passes Parent Model Instead of Agent Definition

When the main loop runs with an OpenAI provider + GPT model and spawns built-in Trace or Investigate agents, those agents receive the parent's GPT model instead of their defined `mimo-v2.5`. The root cause is a combination of an encouraging tool schema description, missing system prompt guards, and an alias fallback that returns the parent model for unrecognized providers.

## How the Override Happens

The Agent tool schema at `src/tools/AgentTool/AgentTool.tsx:91` describes the `model` parameter as:

> "Optional model override for this agent. Takes precedence over the agent definition's model frontmatter. If omitted, uses the agent definition's model, or inherits from the parent."

This framing tells the LLM that `model` is an active control. The enum `['sonnet','opus','haiku']` presents concrete choices. Nothing in the non-coordinator system prompt warns against passing it for built-in agent spawns — only forks are warned (`src/tools/AgentTool/prompt.ts:89`), and coordinator mode explicitly forbids it (`src/coordinator/coordinatorMode.ts:138`), but the main loop has no equivalent guard.

When the LLM passes `model: 'sonnet'` (or similar), the resolution chain is:

1. `AgentTool.tsx:413` — `modelParam = modelIdParam ?? modelEnumParam` flows through without gating
2. `AgentTool.tsx:783` — `model` forwarded to `runAgent()` as `toolSpecifiedModel`
3. `runAgent.ts:411-418` — `getAgentModel(agentDefinition.model, parentModel, model)` receives the LLM's enum
4. `agent.ts:74-86` — `toolSpecifiedModel` takes unconditional priority, bypassing `agentDefinition.model` (`'mimo-v2.5'`)

## Why the Parent Model Leaks

The alias resolution at `src/utils/model/agentAliasFallback.ts:58-81` handles tier aliases (`sonnet`/`opus`/`haiku`) by matching against known providers (openrouter, antigravity, openai, firstParty, bedrock, vertex, foundry). The `mimo` provider is not in this list, so the catch-all at line 81 returns `parentModel` — the parent session's GPT model string. The agent then runs on the `mimo` provider with a model ID that provider cannot serve.

## Agent Definitions Are Correct

Both built-in agents pin their config correctly:

- `src/tools/AgentTool/built-in/traceAgent.ts:99-100` — `provider: 'mimo'`, `model: 'mimo-v2.5'`
- `src/tools/AgentTool/built-in/investigateAgent.ts:106-107` — `provider: 'mimo'`, `model: 'mimo-v2.5'`

When the LLM omits the `model` param, `getAgentModel` falls through to `agentModel` at `agent.ts:103-126`, which resolves `'mimo-v2.5'` correctly via `parseUserSpecifiedModel`. The bug is dormant if the LLM doesn't pass `model`.
