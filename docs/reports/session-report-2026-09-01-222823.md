# Built-in Agent Provider/Model Override Bug: Root Cause Trace

Built-in Trace and Investigate agents declare `provider: 'mimo'` and `model: 'mimo-v2.5'`, but when spawned from a GPT main loop agent, they run on the agent's custom provider with the **parent's GPT model** instead of their declared model. The explicit model configuration is silently ignored.

## Root Cause

The bug has two interacting faults:

**1. Tool-level `model` param overrides agent definition model.** When the LLM passes `model: 'haiku'` (or any tier alias) in the Agent tool call, `getAgentModel` at `src/utils/model/agent.ts:74` enters the `toolSpecifiedModel` branch first, before the agent definition's `model: 'mimo-v2.5'` is ever consulted. The agent definition model is completely bypassed.

**2. Tier alias resolves against session provider, not agent provider.** Inside that branch, `resolveAgentAliasPolicy('haiku', gptModel, getAPIProvider())` at `agent.ts:75-78` calls `getAPIProvider()`. When the LLM passes a tier alias, the resolution uses the session provider (`'openai'`), which maps the alias to `parentModel` (the GPT model) via `agentAliasFallback.ts:69`. The agent's own provider (`'mimo'`) is not consulted for alias resolution.

## Key Code Paths

**Agent definition (correct config, ignored at runtime):**
- `src/tools/AgentTool/built-in/traceAgent.ts:99-100` — `provider: 'mimo'`, `model: 'mimo-v2.5'`
- `src/tools/AgentTool/built-in/investigateAgent.ts:106-107` — `provider: 'mimo'`, `model: 'mimo-v2.5'`

**Provider application (works correctly):**
- `src/tools/AgentTool/runAgent.ts:978-982` — `canApplyAgentProvider('mimo')` returns `true`, agent provider is applied
- `src/tools/AgentTool/runAgent.ts:989` — `runWithForcedProvider({ provider: 'mimo', source: 'agent' })` wraps generator execution

**Model resolution (where it breaks):**
- `src/tools/AgentTool/AgentTool.tsx:413` — `modelParam = modelIdParam ?? modelEnumParam` captures LLM's tier alias
- `src/tools/AgentTool/AgentTool.tsx:783` — tool-level `model` passed to `runAgentParams`
- `src/tools/AgentTool/runAgent.ts:413-418` — `getAgentModel('mimo-v2.5', gptModel, 'haiku', ...)` called with `toolSpecifiedModel = 'haiku'`
- `src/utils/model/agent.ts:74-86` — `toolSpecifiedModel` branch taken, agent definition model skipped entirely
- `src/utils/model/agentAliasFallback.ts:65-69` — `resolveAgentAliasPolicy` for provider `'openai'` returns `parentModel` (GPT model)

**Alias resolution policy:**
- `src/utils/model/agentAliasFallback.ts:58` — `isModelAlias('mimo-v2.5')` returns `false` (concrete ID, not a tier alias), so if `toolSpecifiedModel` were undefined, the agent's model would pass through correctly
- `src/utils/model/agentAliasFallback.ts:65-69` — For `'openai'` provider with a tier alias, returns `parentModel` unconditionally

## Propagation Flow

```
LLM calls Agent({ subagent_type: 'Trace', model: 'haiku' })
  => AgentTool.tsx:413 modelParam = 'haiku'
  => runAgent.ts:413 getAgentModel('mimo-v2.5', gptModel, 'haiku', ...)
  => agent.ts:74 toolSpecifiedModel = 'haiku' => branch taken
  => agent.ts:75 resolveAgentAliasPolicy('haiku', gptModel, 'openai')
  => agentAliasFallback.ts:69 return parentModel (GPT model)
  => Agent runs on provider 'mimo' with GPT model
```

## Conditions

- Triggered when the LLM passes a tier alias (`sonnet`/`opus`/`haiku`) via the Agent tool's `model` enum parameter
- The Agent tool schema at `AgentTool.tsx:91` exposes `model: z.enum(['sonnet', 'opus', 'haiku']).optional()`, inviting the LLM to pass it
- When team-mode is OFF, `providerParam` and `modelIdParam` are silently zeroed (`AgentTool.tsx:311-312`), but `modelEnumParam` flows through
- If the LLM omits `model` entirely, `toolSpecifiedModel` is `undefined` and the agent definition's `model: 'mimo-v2.5'` is used correctly

## Gaps

- Unconfirmed whether the LLM actually passes `model` when spawning built-in agents in practice, or whether it omits it (which would make the bug dormant)
- Unconfirmed whether `CLAUDE_CODE_SUBAGENT_MODEL` env var is set in affected environments, which would independently override the agent model at `agent.ts:93`
- Unconfirmed whether `getAPIProvider()` at `agent.ts:78` returns `'openai'` or `'mimo'` — depends on ALS context from `runWithForcedProvider` at `runAgent.ts:989` being active during generator execution (should be `'mimo'` per ALS semantics, but the alias policy for `'mimo'` at `agentAliasFallback.ts:81` also returns `parentModel`)
