# Sub-Agent Model Inheritance Bug in OpenAI Provider Sessions

Tier aliases on sub-agent definitions (`sonnet`, `opus`, `haiku`) collapse to the parent's model when the session provider is OpenAI. The root cause spans four layers: alias resolution returns `parentModel` for non-Anthropic providers, agent provider scope is never applied at runtime, coordinator mode discards tool-level models, and load-time validation misses agents without explicit providers.

## Root Cause

`resolveAgentAliasPolicy` in `src/utils/model/agentAliasFallback.ts:65-70` returns `parentModel` for all tier aliases when the session provider is OpenAI (or any non-Anthropic provider). The agent's own provider declaration is ignored at runtime because `canApplyAgentProvider` returns `false` when no outer forced provider exists, causing `getAgentModel` to resolve under the session's provider scope.

## Findings by Layer

### Alias Resolution

- `src/utils/model/agentAliasFallback.ts:65-70`: OpenAI policy maps all aliases to `parentModel`. Only GPT-5.x parents get `gpt-5.4-mini` instead.
- `src/utils/model/agent.ts:115-119`: `resolveAgentAliasPolicy` reads `getAPIProvider()` which returns the session provider, not the agent's declared provider.
- `src/utils/model/agent.ts:102-111`: The `inherit` path short-circuits to `getRuntimeMainLoopModel`, returning the parent's exact model string.

### Provider Scope

- `src/tools/AgentTool/runAgent.ts:978-982`: `canApplyAgentProvider` gates whether `runWithForcedProvider` wraps the generator. Returns `false` for agents without a provider.
- `src/utils/forcedProvider.ts:67-73`: Also returns `false` when outer forced provider source is not `'agent'` (team-mode override wins).

### AgentTool Dispatch

- `src/tools/AgentTool/AgentTool.tsx:414`: Coordinator mode sets `model = undefined`, discarding any tool-specified model.
- `src/tools/AgentTool/AgentTool.tsx:311-312`: `providerParam` and `modelIdParam` gated to `teamModeOn` only.
- `src/tools/AgentTool/AgentTool.tsx:587` vs `runAgent.ts:411-418`: Logging resolves model under `runWithAgentProvider` (correct scope), but runtime execution does not — discrepancy between tracked and executed model.

### Validation

- `src/tools/AgentTool/loadAgentsDir.ts:664-676`: Rejects `provider + alias` combos on non-independent-resolving providers. Agents without a provider using aliases on non-Anthropic sessions pass validation silently.

### Propagation

- `src/tools/AgentTool/runAgent.ts:751`: Wrong resolved model becomes sub-agent's `mainLoopModel`, cascading to nested sub-agents.
- `src/query.ts:624-630`: `getRuntimeMainLoopModel` may apply additional session-global overrides on top.

## Open Questions

- Whether OpenAI alias policy returning `parentModel` is intentional design or a bug for agents with explicit model config.
- Whether validation should reject alias models without a provider on non-Anthropic sessions.
- Whether `getRuntimeMainLoopModel` should skip session-global overrides when model was explicitly resolved.
- Whether in-process teammate propagation (`inProcessRunner.ts:1000`) has the same alias collapse issue.
